# MusicMeters

An offline music visualizer built around Prism's native analysis and Canvas meter rendering. The current development build has a static Electron layout editor and MP4 export.

The Prism-based application is GPL-3.0-only. See [the license](LICENSE) and [license and modification notices](LICENSE-NOTICES.md). MusicMeters brand artwork has a separate notice there. Each eventual public binary must be paired with its exact source archive as described in [the release checklist](docs/release-checklist.md); the current portable build is a development preview.

## Run the editor

Set up the pinned Prism checkout and native addon as described in [the Phase 0 report](docs/phase-0-report.md). Keep `ffmpeg` and `ffprobe` on PATH. Then run from the repository root:

```powershell
node phase2/run.cjs
```

Choose **Import / replace audio** to load a WAV, MP3, or FLAC file. Select a timestamp to see a real still frame, add vectorscope, spectrum analyzer, oscilloscope, spectrogram, waveform history, VU, loudness/peak, or waterfall spectrum layers, move or resize them, save a JSON project, and choose **Render MP4**. Vectorscope layers offer five Prism stereo projections, zoom, optional native three-band traces and colors, and optional signed full-band/band correlation indicators. Spectrum layers have independent FFT size, smoothing, frequency scale, range, and side-channel settings. Oscilloscope layers show Prism's left-channel wave with pitch-triggered or free-running display, optional underfill, and optional grid. Spectrogram layers scroll frequency history in either orientation with independent scale, color, and analysis settings. Waveform history layers offer mono left-channel or stereo lanes, scroll speed 1–8, and optional low/mid/high band colors. VU layers offer horizontal or vertical stereo bars, stereo or combined needles, a configurable 0 VU dBFS reference, and colors. Loudness/peak layers show momentary, short-term, or integrated LUFS alongside stereo bars and true peak, with independent readout and colors. Waterfall layers show Prism's native time-evolving spectrum ridges with independent FFT, scale, history, density, smoothing, tilt, and colors. The editor offers 720p and 1080p output at 30 FPS. Project files store an audio path relative to the JSON file.

Use **Snap** above the stage to align dragged layers with the stage edges and center; choose an optional 16, 32, or 64 px grid. Guide lines show active alignments. In the Inspector, **Lock aspect ratio while resizing** keeps a layer proportional when dragging its resize handle or editing width and height. Meter layers also have a rotation control from −180° to 180°. These settings are saved with the project and are shared by the still preview and MP4 renderer.

For a finished composition, choose **Artwork / logo** or **Text** in the Add layer menu. Image layers use a local PNG, JPEG, or WebP file, crop-to-fill or fit-inside, opacity, rotation, and shadow. Text layers have content, font, size, weight, alignment, color, rotation, and shadow. The composition background can be a solid color, gradient, or local image. Layer order is shared across meters, artwork, and text: **Move up** places a layer in front. The project name is metadata; in version 2 projects, visible song and artist lettering comes from text layers. Older version 1 projects retain their original fixed title/subtitle/timestamp display until a new graphic layer or background style upgrades them. Saving a version 2 project copies artwork into a sibling `<project-name>.assets` folder. Keep that folder with the JSON when moving the project. Audio is still referenced separately and is never embedded. If audio or artwork is missing, the editor lists each missing file with a **Relink…** button; save the project after choosing replacements. **Save as…** creates a separate project for the next song.

## Reuse a layout for the next song

Select **Minimal Spectrum**, **Studio Dashboard**, or **Stereo Showcase** from **Layout template**, then press **Use layout**. Position meters and graphics, enter a name, and press **Save current** to store your own template. **Duplicate** creates an editable copy; **Rename selected** renames a custom template. Templates are versioned JSON files in Electron's local user-data `templates` folder. They keep meter settings, layer order, typography, and background styling. A background image is copied into a sibling `.assets` folder. They clear audio, artwork/logo image paths, and all text content, while preserving each text layer's style and position. When a template is used with imported audio, layers named **Song title** receive an editable title suggestion. Pick artwork for any visible empty image layer before export.

For another song, press **Import / replace audio** and, if needed, choose new artwork and edit the title text. The app clears the old still analysis and recomputes it from the new song. It remembers the last selected template and export size locally. Export defaults to **1080p at 30 FPS**; the save dialog suggests `<title>_visualizer.mp4`. An existing MP4 is never silently overwritten: choose another name or cancel. Project JSON and its `.assets` folder are portable together; templates remain in this device's Electron user data unless copied separately with their asset folders.

For a developer smoke test, generate the synthetic fixtures with `python phase1/make-fixtures.py` and run `node phase2/run.cjs --audio artifacts/phase1/fixtures/stereo-10s-48k.wav`.

The [Phase 5 report](docs/phase-5-report.md) documents the song-switch gate and its limits. Earlier [Phase 4 report](docs/phase-4-report.md), [phase reports](docs/phase-3-8-report.md), and the [meter parity matrix](docs/meter-parity.md) track composition and meter verification.

## Developer setup and Windows portable build

This repository is developed on Windows x64. Install Node.js 24 LTS, Python, Visual Studio 2022 C++ build tools, and FFmpeg/FFprobe on `PATH`. From a fresh checkout, clone Prism into the ignored `upstream/prism` directory and check out commit `49721802252b115d169e353c98b27408daa5e2b7`. In that Prism directory, run `npm ci --ignore-scripts --no-audit --no-fund` and `npm run build:native`. The pinned `node-gyp` 10 build requires Visual Studio 2022; some Windows hosts need Visual Studio environment variables as described in [the Phase 0 setup record](docs/phase-0-report.md). In `phase6/electron-runtime`, run `npm ci --ignore-scripts --no-audit --no-fund` and `node node_modules/electron/install.js` to install the exact Electron version in its lockfile. Astrofox is a source reference and is not needed to build the application.

From the repository root, run `python phase1/make-fixtures.py` to prepare the ignored unit-test audio, `node phase2/build.cjs`, then `node phase2/run.cjs` to open the editor. To create a portable development package, run `node phase6/package-windows.cjs --output artifacts/phase6/my-new-package` and launch its `electron.exe`. The output directory must not already exist. The package includes the Electron runtime, built renderer code, MusicMeters window icon and brand assets, and the pinned Prism native addon. It requires system FFmpeg and FFprobe; neither binary is bundled. Work files and export analysis caches are written to the current user's temp directory, not the package folder. Export checks the output drive for a working-space estimate before analysis and cleans up partial MP4s on failure or cancellation.

The [Phase 6 report](docs/phase-6-report.md) records the synthetic export, audio matrix, two-minute run, regressions, and release limitations. The portable folder is a local development preview. Review the [release checklist](docs/release-checklist.md) and [public release review](docs/public-release-review.md) before distributing a public binary. Linux and macOS builds have not been validated; installed-font discovery and this packaging script currently require Windows.
