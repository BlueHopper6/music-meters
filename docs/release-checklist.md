# Windows development preview and release checklist

## Reproduce the build

1. On Windows x64, install the latest patched Node.js 24 LTS, Python, Visual Studio 2022 C++ build tools, FFmpeg, and FFprobe. Verify `node`, `python`, `ffmpeg`, and `ffprobe` on `PATH`.
2. For development, clone this repository, clone `https://github.com/Boof2015/prism.git` into ignored `upstream/prism`, and check out `49721802252b115d169e353c98b27408daa5e2b7`. A paired release source archive already contains that exact Prism tree and a `.musicmeters-prism-commit` marker, so no second Prism clone is needed when rebuilding from that archive.
3. In `phase6/build-tools`, run `npm ci --ignore-scripts --no-audit --no-fund` and `npm audit --audit-level=low`. From the repository root run `node phase6/build-native.cjs`. This installs only locked esbuild, node-gyp, TypeScript, and node-addon-api, not Prism's unused development tree. If node-gyp cannot find Visual Studio 2022, use the host-specific environment setup described in `docs/phase-0-report.md`.
4. In `phase6/electron-runtime`, run `npm ci --ignore-scripts --no-audit --no-fund` and `node node_modules/electron/install.js`. `phase6/electron-runtime.cjs` rejects a missing or wrong-version runtime.
5. From the repository root, run `python phase1/make-fixtures.py`, `node phase2/build.cjs`, and the unit command in `docs/phase-6-report.md`. Build a fresh portable folder with `node phase6/package-windows.cjs --output artifacts/phase6/<new-name>`.
6. Confirm `resources/app/phase2/editor-app/assets/brand/music-meters.ico` exists in the package. Run `node phase6/test/run-security.cjs <package-dir> <new-artifact-dir>`, `node phase6/test/package-smoke.cjs <package-dir> <new-artifact-dir>`, `node phase6/test/run-repeat.cjs --package <package-dir> <new-artifact-dir>`, `node phase6/test/audio-copy.cjs <package-dir> <new-artifact-dir>`, `node phase6/test/run-audio-copy-editor.cjs <package-dir> <new-artifact-dir>`, `node phase6/test/audio-matrix.cjs <package-dir> <new-artifact-dir>`, and `node phase6/test/run-preview-performance.cjs <package-dir> <new-artifact-dir>` with a fresh output directory for each. The checks cover security policy, MP4/AAC, MKV stream copy, decoded audio, output frames, same-session export, and late-song multi-meter preview responsiveness. Check stage controls and editor/export still parity. The Windows CI workflow runs these checks on pull requests, but a local run does not establish that hosted CI passed.

## Pair an exact source archive with a release build

1. Commit all intended source changes, confirm a clean tracked working tree, and build a **new** portable folder from that commit. The package records the MusicMeters commit, Prism commit, Electron version, and whether tracked source was dirty in `BUILD-PROVENANCE.json`.
2. Beside the package, run `python phase6/release-source.py --package <package-dir> --output <new-source-archive.zip>`. The tool refuses an existing output, a dirty tracked tree, a modified or unpinned Prism checkout, and a package built from another commit. It writes `SOURCE-ARCHIVE.json` into the package with the archive name and SHA-256 checksum.
3. Run `python phase6/test/source-archive.py <package-dir> <source-archive.zip> <new-extraction-dir>`. Inspect the extracted `musicmeters/SOURCE-MANIFEST.json`, `LICENSE`, `LICENSE-NOTICES.md`, `upstream/prism/LICENSE`, and `third_party/node-addon-api/LICENSE.md`. The archive carries source, build scripts, lockfiles, and three runtime icons, not generated binaries or npm caches; `samples/` historical media and unused brand images are omitted because they are not needed to modify or rebuild the program. The runtime icons have a separate artwork notice in `LICENSE-NOTICES.md`: a complete, unchanged official release and its matching source may be shared with the branding; modified or repackaged builds must rebrand unless separately authorized by the logo owner.
4. From the extracted `musicmeters` directory on Windows x64, run `npm ci --ignore-scripts --no-audit --no-fund` in `phase6/build-tools`, then `node phase6/build-native.cjs` from the extracted root; run `npm ci --ignore-scripts --no-audit --no-fund` and `node node_modules/electron/install.js` in `phase6/electron-runtime`. Run `python phase1/make-fixtures.py`, `node phase2/build.cjs`, `node phase6/package-windows.cjs --output <fresh-package-dir>`, and `node phase6/test/package-smoke.cjs <fresh-package-dir> <fresh-smoke-dir>` from the extracted root. Network access is needed to install pinned npm dependencies; the included node-addon-api source is also available for inspection and modification.
5. Publish the binary package and its named archive together, with equivalent access at the same download location and no additional source charge. Keep each pair available while the binary is offered. Check the archive checksum and package provenance before uploading. The source for one release must not be silently replaced by a later commit. The GitHub auto-generated source archive alone lacks the ignored Prism tree and is insufficient.

## Use the app

Run `electron.exe` in the portable folder while FFmpeg and FFprobe are on `PATH`. Import a local WAV, FLAC, or MP3 song; choose or edit a template; select a preview timestamp; set artwork/text; and render a video. Export defaults to 1080p/30 with H.264 video in MP4 and lossy AAC audio targeting up to 320 kb/s (with lower targets for mono or low-sample-rate inputs; observed bitrate depends on the signal). Choose MKV source-audio copy for supported MP3, FLAC, and WAV/PCM inputs; this remuxes audio without re-encoding it. MP3 source audio remains lossy. The MKV file and MP3 playback padding are not byte-identical to the source audio file. The save dialog and output extension follow the choice, and existing videos are never silently overwritten. Save the project JSON with its sibling `.assets` folder; relink missing audio or artwork after moving it. Templates and preferences are stored in Electron user data for the current account.

## Before any public binary distribution

- Resolve every open item in [the public release review](public-release-review.md), including the final artwork and GPL distribution review and the exact binary/source pair for the combined GPL-3.0-only Prism-based application.
- Keep `MUSICMETERS-LICENSE.txt`, `LICENSE-NOTICES.md`, `PRISM-LICENSE.txt`, `PRISM-THIRD_PARTY_NOTICES.md`, `PRISM-REFERENCE_DEPENDENCIES.md`, `DR_LIBS-LICENSE.txt`, `R8BRAIN-LICENSE.txt`, `NODE-ADDON-API-LICENSE.md`, `THIRD_PARTY_NOTICES.md`, `BUILD-PROVENANCE.json`, `SOURCE-ARCHIVE.json`, and Electron's `LICENSE` and `LICENSES.chromium.html` in the release package.
- Use an Electron stable build containing the latest applicable Node.js security fixes; the current stable 45.0.0 contains Node 24.22.0, so this gate remains open for the October 2026 Node fixes.
- FFmpeg/FFprobe command-line executables are system dependencies in this build. Electron's copied runtime includes `ffmpeg.dll` with a notice in `LICENSES.chromium.html`. If a future package bundles the FFmpeg command-line executables, review the exact binaries' configuration and license obligations first.
- Validate the final binary on a clean Windows x64 machine with FFmpeg installed. Recheck antivirus/SmartScreen behavior, install location write permissions, and actual native dialog flows. No installer, signing, or update channel is supplied yet.
- Treat Linux and macOS as unverified. Font discovery uses Windows `System.Drawing`, the native addon is built for the local OS, and `package-windows.cjs` copies `electron.exe`.

## Known test limits

The automated low-disk test simulates a volume with insufficient free bytes and verifies the preflight error; the real disk was not filled. The encoder-failure test substitutes an executable that rejects FFmpeg arguments and verifies partial-file cleanup. Real hardware disk exhaustion, system FFmpeg removal during export, native Windows file pickers, and a public release installation were not exercised.
