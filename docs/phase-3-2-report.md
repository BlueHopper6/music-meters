# Phase 3.2: Prism oscilloscope

## Architecture and provenance

- Based on merged main `a38799a` and pinned Prism `49721802252b115d169e353c98b27408daa5e2b7`. Astrofox code is not used.
- Reuses Prism's `native/src/oscilloscope.cpp`, `native/src/oscilloscope.h`, and `native/src/main.cpp` N-API entry points for the filtered sample buffer, pitch detection, sub-sample trigger, and interpolated display samples. Reuses the original `src/renderer/visualizers/Oscilloscope.ts` Canvas painter and `src/renderer/audio/native/oscilloscopeDisplaySamples.ts` normalization rule. Prism's source checkout is unchanged.
- The build inserts a narrow public `renderFrame()` entry point in memory. For this offline snapshot painter it also marks the precomputed frame as past Prism's 4096-sample live-input warmup. The renderer receives only Prism-produced, already-triggered wave samples through a native-analyzer adapter; its wave and optional underfill are painted by Prism's Canvas code. No screen recording or replacement meter drawing is used.
- `phase3/oscilloscope.cjs` runs one continuous left-channel native analysis pass for the requested modes. When both pitch-locked and free-running layers are present, it captures both modes from the same native buffer each frame, with pitch analysis first. Export stores fixed-size temporary waveform records on disk and reads them sequentially; preview decodes from the beginning to the selected frame so pitch history and backward seeks match export. Temporary records are removed on success, cancellation, and errors.
- Version 1 projects remain compatible. Oscilloscope layers independently save position, size, opacity, color, pitch lock, underfill, and grid. A four-layer project containing spectrum, vectorscope, and two unlike oscilloscopes was saved, reopened, previewed, and rendered.

## Verification

The generated ten-second 48 kHz stereo fixture has silence at 0–2 s, 440 Hz in-phase at 2–4 s, anti-phase at 4–6 s, left-only at 6–8 s, and 1 kHz in-phase at 8–10 s. The oscilloscope follows Prism's left-channel feed, so its wave remains present in the anti-phase and left-only sections; the vectorscope and spectrum show their channel differences. A resampled 96 kHz copy and the existing 44.1 kHz mono fixture exercised sample-rate handling.

## Performance and limits

The ten-second, four-layer 1080p export took **19.659 s** on this machine. It rendered 300 frames; reported render/PNG bridge time was 16.557 s, vectorscope analysis time 0.085 s, and encoder backpressure time 0.343 s. Peak **Electron main-process** RSS was 142,299,136 bytes; this excludes the renderer, FFmpeg, and disk caches. With two oscilloscope modes at 48 kHz, temporary wave records occupy about 4.9 MB per ten seconds, in addition to the spectrum cache. These measurements are observations, not guarantees.

The native pitch detector smooths changes over time: at 9 s, one second into the 1 kHz section, it reported approximately 883 Hz although the displayed sample wave measured approximately 1 kHz. The source stills and export matched; faster pitch tracking would require an upstream DSP behavior change. Pitch analysis advances once per 30 FPS output frame, so transient behavior can differ from live Prism's update cadence. Only left-channel waveform input is supported, following Prism. Previewing a long song reprocesses from its start and may be slow. The app is still a development build, and later meter and composition phases remain outstanding.
